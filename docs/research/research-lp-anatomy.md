# 国内BtoB LP アナトミー調査 — Web/LP デザインシステム設計仮説の検証

対象: 日本のBtoB SaaS の **Web / LP 面のみ**（`@polastack/gtm-design-system` 側）。
業務システムUI（`@polastack/design-system`）の設計とは切り離して読むこと。

調査日: 2026-08-02
調査手法: WebFetch（HTML→markdown変換）+ curl による生HTML/CSSの直接取得 + 補助的なWeb検索

## 手法と限界（先に読むこと）

**事実として記録したもの**

- WebFetch がページ本文を返した場合の、セクション見出し・CTA文言・数値訴求・ロゴ社数
- curl で取得した生HTML / CSS 内の `position:fixed` ルール、クラス定義、インラインフォーム要素

**推測・未検証として区別したもの**

- ブラウザレンダリングはしていない。**スクリーンショット確認は一切行っていない。**
  したがって「背景の明暗リズム」「実際の視覚的な強調面」は原則として判定できない。
- CTAの「軽い/重い」分類は文言からの解釈であり、筆者の判断。
- 追従CTAは静的HTML/CSSからの検出。**検出できなかった = 存在しない、ではない**
  （React/Next のクライアントレンダリングや、後読みCSSで注入される可能性がある）。

### 2-1. セクション順序の共通パターン

### 仮説② リズム規則: 背景は明↔淡を交互、ヒーローと最終CTAのみ強調面、プライマリCTAはページに2箇所まで

**判定: 前半2つはデータ不足、「CTA 2箇所まで」は修正が必要**

**(a) 背景の明↔淡交互 → データ不足**
ブラウザレンダリングもスクリーンショット取得も行っていないため、実際の背景の明暗リズムは**一切検証できていない**。
生CSSから拾えた断片（カミナシ: ヘッダー `#FFFFFF`、アクセント `#0360e5`、CTA `#ffdb22`）だけでは
セクション背景の交互性は判定できない。**この仮説を検証するにはスクリーンショットベースの再調査が必要。**

**(b) ヒーローと最終CTAのみ強調面 → データ不足だが、反証の気配あり**

- 「最終CTA面がフッター直前にある」ことは **10/12（83%）で確認でき、この部分は支持**
- ただし「**強調面がそこだけ**」という排他性は検証できていない。実際には
  カミナシが本文中に「導入までの流れ」「セミナー」など多数の面を持ち、
  freee会計・バクラクは**本文中にセキュリティ専用セクション**を持つ。
  Bill One は本文中に「Bill One Bank」の独立ブロックを持つ。
  強調面が2枚に収まる構造には見えない、というのが現時点の印象（**推測**）

**(c) プライマリCTAはページに2箇所まで → 修正が必要（明確な反証）**

- 総CTA数の中央値は **15〜16本**。**2本のページは0件**
- ただし**ラベルの種類数は2種が最頻**（バクラク経費精算 / freee会計 / MF / SmartHR / chatwork / カミナシ）
- 実装形は **「2種類のプライマリCTAラベル × 5回前後の反復」**

に書き換えるべき。** デザインシステム側では
「CTAラベルはページ単位で2種に制約するトークン/Propsを持ち、CTABand コンポーネントを繰り返し置ける」設計が実態に合う。

### 仮説③ 2段階CTA: 「資料ダウンロード（軽い）」と「問い合わせ/デモ（重い）」の併置

**判定: ページ全体では支持。ファーストビュー限定では修正が必要**

**ページ全体で見れば: 支持（強い）**
19ページ中、軽（資料DL / 料金表DL / お役立ち資料）と重（問い合わせ / 見積もり / デモ / トライアル）の**両方を持つページは17/19**。
持たないのは LayerX（corporate-top）と Bill One invoice（重が「お問い合わせ」のみ）程度。

**FVに限れば: 併置は 7/16（44%）で、過半に届かない**

| FVの構成    | 件数  | 示唆                                                                     |
| ----------- | ----- | ------------------------------------------------------------------------ |
| 軽 + 重     | 7     | SmartHR、freee会計、freee人事労務、MF、Bill One invoice、chatwork、josys |

| 軽1本のみ   | 1     | カミナシ（重は追従要素に逃がす）                                         |
| 重のみ      | 1     | HRBrain                                                                  |

**重要な修正点: 「軽 + 軽」という第3のパターンが実在する。**
バクラクは全ページで **「＼5分でわかる資料をプレゼント／ メールで資料を受け取る」＋「＼詳しい料金がわかる／ 料金表をもらう」**
という**2本とも軽いCTA**を並べている。
これは「資料DL vs 問い合わせ」の軽重2段階ではなく、**「何の資料が欲しいか」の分岐**であり、質的に別の設計。

またセルフサーブ型（freee / MF / chatwork / kintone）では
重いCTAが「問い合わせ」ではなく**「無料で始める／無料トライアル」**になる。
この場合の「重さ」は営業接触ではなく**アカウント作成**であり、心理的な重さの性質が違う。

→ **CTAペアの型を3つに拡張すべき:**

1. `軽（資料DL）+ 重（問い合わせ・デモ）` — 営業主導型
2. `軽（資料DL）+ 重（無料トライアル・無料で始める）` — セルフサーブ型
3. `軽（サービス資料）+ 軽（料金表）` — 資料分岐型（バクラク・ANDPAD）

さらに、**「ご相談だけでもOK お問い合わせ」（HRBrain）のように重いCTAに"重さを下げる修飾ラベル"を付ける**慣行がある。
CTAコンポーネントに `caption` / `kicker` スロット（＼／囲みの上乗せ文言）は**ほぼ必須**。
実測で確認できた kicker: 「＼5分でわかる資料をプレゼント／」「＼詳しい料金がわかる／」「＼カミナシがもっとわかる3点セット／」「＼同業他社の事例を紹介中！／」「＼5日の業務がたった1日で終わる！／」「クレジットカード不要」「ご相談だけでもOK」。

- 「モバイル画面下部の全幅固定CTAバー」を**国内BtoBの標準装備と断定する根拠はない**
- 実測で確認できた追従形態は **①固定ヘッダー内CTA ②右下フローティングカード（閉じられる）** の2つ
- freee の事例が示すように、**下部固定バーは"デザインシステムに部品として持ち、LP単位でON/OFFする"のが現実的な運用**

→ **設計への反映:**
「追従CTAスロット」を用意すること自体は妥当だが、**配置を bottom 固定に決め打ちしない**。
`position: header-sticky | bottom-bar | corner-card` の3形態を持ち、
ページ型ごと・ブレークポイントごとに選択でき、**corner-card には必ず dismiss（×）を持たせる**設計が実測に合う。
`z-index` は カミナシ実測で ヘッダー=2 / フローティング=5。

**この仮説は再検証を推奨。** スクリーンショットまたはヘッドレスブラウザでのレンダリング後DOM取得ができれば決着する。

### 仮説⑤ 導入ロゴは6社未満だと逆効果

**判定: 修正が必要（因果は検証不能。ただし配置の実態は仮説と別の示唆を与える）**

**「逆効果」という因果の検証は不可能。** LPのCVRデータは非公開であり、今回の手法では検証できない。以下は**分布の観察**のみ。

**観察された事実:**

1. **6社未満は 1件のみ（josys 3社、しかも英語グローバルサイト）。日本語ページには0件**
   → 「少数掲載」という選択が実際にほぼ取られていないのは事実
2. しかし**より重要なのは、掲載社数が二極化していること**

| 選択                                          | ページ数          | 実態                                                                        |
| --------------------------------------------- | ----------------- | --------------------------------------------------------------------------- |
| **0社（ロゴ帯を置かず数値バッジに振り切る）** | **6 / 19（32%）** | freee会計、freee人事労務、MFクラウド会計、HRBrain、LayerX、Bill One invoice |
| 6〜8社（事例セクション内に少数）              | 2                 | SmartHRトップ（6社）、Bill Oneトップ（8社）                                 |
| **14社以上（カルーセル）**                    | **5**             | chatwork 14、kintone 20+、ANDPAD 30+、バクラク 38-40、カミナシ 42+          |

3. **「0社」は劣った選択ではない。** freee は「有料課金ユーザー企業数62万」「シェアNo.1 56.3%」という
   **数値の圧倒性でロゴを不要にしている**。HRBrain も「4,000社以上」の数値のみ。
   つまり **ロゴ帯と数値訴求は代替関係にある**
4. SmartHR の 6社は「ロゴ帯」ではなく**事例カードに付随するロゴ**であり、
   FV直下のカルーセルとは役割が違う。単純な社数比較は成立しない

→ **規則を書き換えるなら:**
「6社未満は逆効果」ではなく
**「社会的証明スロットには『ロゴカルーセル（14社以上を推奨）』と『数値バッジ』の2実装があり、どちらかを必ず置く。
中途半端な少数ロゴ帯（1〜5社）は実例が存在しないため避ける。
少数しか出せない場合は、ロゴ帯ではなく事例カードに紐付ける形（SmartHR / Bill One 方式）にする」**
が実測に即している。

**グレースケール化の有無は判定できていない（データ不足）。** ロゴ画像のCSS filter を確認していない。
