# ファーストビューの占有 — ヒーローは1画面を持つべきか（実測）

**日付**: 2026-08-16
**動機**: PR #170（セクション余白の半減）のあと、ブランドオーナーから
「ヒーローの下のセクションがファーストビューに入ってきて、ヒーローが弱くなった」という指摘。
余白を戻すべきか、別の手段で担保すべきかを実測で決める。

**方法**: Playwright + Chromium、ビューポート 1440×900、実サイトを実レンダリング。
`--spacing-section-*` を触った PR の影響を測るのが目的なので、指標は
**「次セクションの見出し（最初の `h2`）が現れる y 座標」**にした。
ヒーロー要素そのものの高さは自動判定が当てにならない（後述の限界）。

---

## 1. 実測（国内11 + 海外2、1440×900）

| サイト | 最初の `h2` の y | ファーストビュー（900px）との関係 |
| --- | ---: | --- |
| LayerX | 2118px | 画面外。ヒーローが1画面ちょうど（高さ 900px） |
| ANDPAD | 1725px | 画面外。ヒーローが1画面を占有（スクショで確認） |
| Linear（海外） | 1531px | 画面外。ヒーロー高 1024px |
| kintone | 1230px | 画面外 |
| カミナシ | 1037px | 画面外。ヒーロー帯は 570px で終わり、残りは**証明帯**（数値+ロゴ）が埋める |
| マネーフォワード | 930px | ほぼ画面端 |
| バクラク | 894px | ほぼ画面端。ヒーロー下端 750px |
| Stripe（海外） | 854px | ほぼ画面端。ヒーロー下端 761px |
| SmartHR | 696px | **画面内**。次セクションの見出しと本文が下 260px を占める |
| freee会計 | 644px | **画面内** |
| Chatwork | （`h2` なし） | ヒーローが `min-height: calc(100% - 48px)` で1画面を占有 |
| Bill One | （`h1` なし・判定不能） | — |
| HRBrain | （`h1` なし・判定不能） | — |

**中央値は約 980px。** 母集団13件のうち、次の見出しがファーストビューに
入っているのは 2件（SmartHR / freee会計）だけで、**大勢は「ヒーロー（＋その章に属する証明帯）で1画面」**。

補足: カミナシは「ヒーロー帯 + 証明帯」で1画面を作っている。これは我々の
`LandingPage` の `attached`（ヒーロー直下の証明帯）と同じ構造で、
**次の"章"の見出しが入るのとは意味が違う**。バクラクも同型。

## 2. 手段 — 実測では高さを視野基準で持っている

Chatwork は `min-height: calc(100% - 48px)`、LayerX はヒーロー高がちょうど 900px、
Linear は 1024px。**パディングでファーストビューを埋めているサイトは無い。**
当然で、パディングは固定値なのでコピー量と視野の高さに結果が左右される。

## 3. 我々の実測（同条件）

| 状態 | ヒーロー下端 | 占有 | 次の見出し |
| --- | ---: | ---: | ---: |
| PR #170 前（CorporateTop / trust） | 833px | 93% | 993px |
| PR #170 後（余白半減） | 641px | 71% | **721px** ← 母集団の下位2番目 |
| `--hero-min-height` 導入後 | 828px | 92% | 908px |

製品LP（product）は #170 前後どちらでもヒーロー下端 828px 付近で、
覗くのは証明帯（カミナシ・バクラク型）。**問題が出たのは trust ページ**だった。

## 4. 決定

`--hero-min-height: calc(92svh - 4rem)`（4rem = ヘッダー高）を導入し、
`HeroSection` の `min-height` に充てる。コンテンツは縦中央寄せ。

- **92%** にしたのは、下 8%（1440×900 で 72px）に次の面を覗かせて
  「下に続く」ことを示すため。実測でも バクラク 894px / Stripe 854px と
  「見出しは画面外・面だけ覗く」型がある。100% にすると手がかりが消える
- **`svh`** を使うのは、モバイルのツールバー伸縮で高さが揺れないため
- **campaign トーンは適用外**（`--hero-min-height: 0`）。
  「密度を上げてファーストビューに情報を寄せる」というトーンの定義と衝突するため

## 5. この調査の限界

- **ヒーロー要素の自動判定は失敗した。** 「`h1` を含む全幅の祖先」で辿る方式は
  ANDPAD・カミナシ・マネーフォワード・kintone で 100px 前後の要素を拾ってしまい使えなかった。
  上表は `h2` の座標とスクリーンショットの目視で確定させている
- `h1` を持たないサイト（Bill One / HRBrain）は母集団から落ちている
- 1ビューポート（1440×900）のみ。縦に短い画面（1366×768）での他社挙動は測っていない
- 遅延読み込みの画像が未描画のまま撮れているページがある（ANDPAD の右側画像）。
  高さの判定には影響しない位置だが、見え方の評価には注意
